## 이것만 알아두세요

앱을 만들기 전에 저장 방식을 정해 두면 나중에 크게 고치는 일이 줄어듭니다.

판단 기준은 간단합니다. 나 혼자, 한 대의 기기에서 쓰면 LocalStorage로 충분합니다. 하나라도 아니면 데이터베이스가 필요합니다.

## 여섯 개의 질문

만들기 전에 순서대로 답해 보세요. 중간에 "예"가 나오면 거기서 답이 정해집니다.

1. **데이터를 저장해야 합니까?** 아니라면 저장 기능이 필요 없습니다. 타이머나 무작위 뽑기처럼 매번 새로 시작해도 되는 앱이 여기에 해당합니다.
2. **현재 기기에서만 써도 됩니까?** 예라면 LocalStorage로 충분합니다. 아니라면 데이터베이스입니다.
3. **여러 사람이 같은 데이터를 봐야 합니까?** 예라면 데이터베이스입니다.
4. **변경 내용이 바로바로 보여야 합니까?** 예라면 실시간 동기화까지 필요합니다.
5. **사용자를 구분해야 합니까?** 예라면 로그인이 필요합니다.
6. **사용자마다 할 수 있는 일이 다릅니까?** 예라면 권한 관리까지 필요합니다.

앞의 두 질문에서 끝났다면 이 과정에서 배운 것으로 충분합니다. 세 번째 이후에서 걸렸다면 [데이터베이스 연결하기](/database) 과정으로 넘어가면 됩니다.

## 표로 보기

| 만들려는 앱 | LocalStorage | 이유 |
| --- | --- | --- |
| 개인 업무 체크리스트 | 충분합니다 | 내가 내 컴퓨터에서 혼자 씁니다 |
| 수업용 타이머 설정 | 충분합니다 | 설정값만 남기면 됩니다 |
| 자리배치 저장 | 충분합니다 | 교실 컴퓨터 한 대에서 씁니다 |
| 개인 메모장 | 충분합니다 | 나만 보는 기록입니다 |
| 학습 진행률 표시 | 충분합니다 | 사용자 각자의 기기에 남으면 됩니다 |
| 여러 교사가 함께 쓰는 업무 목록 | 부족합니다 | 각자의 브라우저에 따로 쌓입니다 |
| 학생이 제출하고 교사가 확인하는 앱 | 부족합니다 | 서로 다른 기기의 데이터를 봐야 합니다 |
| 학교 컴퓨터와 집 노트북에서 같이 쓰는 앱 | 부족합니다 | 기기가 바뀌면 데이터가 따라오지 않습니다 |
| 실시간 학급 상태판 | 부족합니다 | 변경이 즉시 공유되어야 합니다 |
| 로그인이 필요한 앱 | 부족합니다 | 사용자를 구분해 저장해야 합니다 |
| 학기 내내 쌓이는 중요한 기록 | 권하지 않습니다 | 브라우저 데이터를 지우면 사라집니다 |
| 학생 개인정보가 들어가는 앱 | 쓰면 안 됩니다 | 보호가 필요한 정보를 두기에 적합하지 않습니다 |

## 애매할 때의 기준

표를 봐도 애매한 경우가 있습니다. 그럴 때는 두 가지를 생각해 보세요.

**사라지면 곤란합니까?** 다시 만들면 되는 데이터라면 LocalStorage로 시작해도 됩니다. 사라지면 복구할 수 없는 기록이라면 처음부터 데이터베이스로 갑니다.

**혼자 쓰는 것이 확실합니까?** "나중에 옆 반 선생님도 쓰면 좋겠는데"라는 생각이 든다면, 그 순간이 데이터베이스가 필요해지는 시점입니다.

## 먼저 만들고 나중에 옮겨도 됩니다

지금 판단이 어렵다면 LocalStorage로 먼저 완성하세요.

앱을 완성해 봐야 무엇이 부족한지 알게 됩니다. 처음부터 데이터베이스를 준비하다가 앱을 끝내지 못하는 것보다, 작게 완성하고 필요할 때 옮기는 편이 훨씬 낫습니다.

옮기는 것도 Claude에게 요청하면 됩니다. 이때는 현재 상태를 자세히 설명하는 것이 중요합니다.

## 옮길 때는 이렇게 말합니다

<PromptBox>
현재는 교사용 체크리스트가 LocalStorage에 저장되고 있어.

이제 학교 컴퓨터와 개인 노트북에서 같은 데이터를 사용하고 싶어. Google 로그인 후 로그인한 사용자 자신의 체크리스트만 볼 수 있게 만들고 싶어. Firebase를 사용해서 구현해 줘.

먼저 현재 프로젝트 구조를 분석하고 구현 계획을 설명한 뒤 작업해 줘. 기존 체크리스트 기능과 디자인은 변경하지 마.
</PromptBox>

이 요청에는 일곱 가지가 들어 있습니다. 지금 어떻게 동작하는지, 무엇을 저장할지, 누가 쓸지, 여러 기기에서 쓰는지, 실시간이 필요한지, 로그인이 필요한지, 그리고 기존 기능을 지켜 달라는 것입니다.

"Firebase 붙여 줘" 한마디로는 이 중 어느 것도 전달되지 않습니다. 필요한 것을 먼저 설명하는 습관이 결과를 결정합니다.

자세한 내용은 [언제 데이터베이스가 필요한가요?](/database/when-you-need-a-database)에서 이어집니다.

## 잘 안 된다면

<Troubleshoot>
<Problem title="데이터베이스가 필요한지 아닌지 아직도 모르겠어요">
두 번째 질문 하나만 보세요. "이 앱을 다른 컴퓨터에서도 열 일이 있는가." 없다면 LocalStorage로 시작하면 됩니다.
</Problem>
<Problem title="LocalStorage로 만들었는데 지금 옮겨야 해요">
지금까지 쌓인 데이터를 옮기고 싶다면 요청에 그 내용을 함께 넣으세요. "지금 LocalStorage에 있는 데이터를 처음 로그인할 때 한 번 옮겨 주는 기능도 넣어 줘"라고 말하면 됩니다.
</Problem>
</Troubleshoot>
