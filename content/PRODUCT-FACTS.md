# 제품 사실 시트 (콘텐츠 작성 시 기준)

콘텐츠에 Claude와 관련 도구를 설명할 때 아래 범위 안에서만 단정한다.
여기에 없는 세부 사항(버튼의 정확한 위치, 메뉴 이름, 가격, 사용량 한도)은 단정하지 말고
"버전에 따라 다를 수 있습니다", "공식 안내를 확인하세요"로 처리한다.
없는 기능을 지어내지 않는다.

## Claude 전반

- Claude는 Anthropic이 만든 AI 모델이자 그 모델을 쓰는 앱들의 이름이다.
- 사용 방법은 세 가지로 소개한다. Chat(같이 생각하기), Cowork(일 맡기기), Code(직접 만들기).
- 웹(claude.ai), 데스크톱 앱(Windows/Mac), 모바일 앱이 있다. 컴퓨터의 폴더를 다루는 일(Cowork 방식)과 Claude Code 앱은 데스크톱 앱에서 쓴다.
- 2026년 9월부터 Chat과 Cowork가 하나의 대화창으로 합쳐지고 있다(단계적 적용, 유료 요금제부터). 새 화면에서는 모드를 고르지 않고 한 대화창에서 모든 것을 요청한다. 적용 전 계정은 입력창 근처에 "Chat"과 "Cowork" 선택지가 그대로 보인다. 한 번 새 화면으로 바뀐 계정은 되돌아가지 않는다. 이 사이트는 "Chat·Cowork·Code"를 부탁하는 방식 세 가지의 이름으로 계속 쓰되, 새 화면에서는 Chat과 Cowork가 같은 대화창이라는 점을 함께 안내한다. 자세한 사실은 아래 "Claude Cowork" 절.
- 계정은 이메일 또는 Google 계정으로 만든다. 무료로 시작할 수 있고, 유료 요금제가 있다.
- 일부 기능(예: Cowork, Claude Code)은 요금제나 지역에 따라 제공 여부가 다를 수 있다. 구체적인 금액과 한도는 바뀌므로 쓰지 않는다.
- 모델 선택 메뉴가 있다. 초보자는 기본 선택을 그대로 쓰면 된다. 모델 이름을 나열하지 않는다.

## Claude Chat

- 화면 구성: 왼쪽에 대화 목록과 새 대화 버튼, 가운데 대화 영역, 아래쪽 입력창. 입력창 근처에 파일 첨부 버튼과 모델 선택이 있다.
- 파일 첨부: PDF, 문서, 표, 이미지 등을 끌어다 놓거나 첨부 버튼으로 넣는다. 화면 캡처 이미지를 붙여 넣을 수 있다.
- 대화는 이어진다. 앞의 내용을 기억하고 수정 요청을 반영한다.
- 프로젝트(Projects): 관련 대화와 자료를 한곳에 모아 두는 기능. 프로젝트에 넣어 둔 자료는 그 프로젝트의 모든 대화에서 참고된다. 프로젝트 지침(설명)을 적어 둘 수 있다.
- 결과물이 표, 문서, 코드처럼 길거나 구조적이면 옆 패널(Artifacts)에 따로 표시될 수 있다. 이 용어는 필요할 때만 쓴다.
- 답변은 복사할 수 있고, 다시 생성할 수 있다.

## Claude Cowork (일 맡기기)

두 가지 화면이 한동안 공존한다. 콘텐츠는 두 화면 모두에서 맞게 읽히도록 쓴다. "Cowork 영역", "Cowork 탭"처럼 별도 영역을 전제하는 표현은 쓰지 않고, "Cowork 방식", "일을 통째로 맡기기"로 쓴다. 두 화면의 차이는 `cowork/one-claude` 한 페이지에서 설명하고 다른 페이지에서는 그 페이지로 보낸다.

- 이전 화면: Claude 데스크톱 앱에서 입력창 근처의 "Cowork" 선택지로 들어가 작업 폴더를 지정한다.
- 새 화면(2026년 9월부터 단계적): Chat과 Cowork가 한 대화창이다. 모드를 고르지 않고 요청하면 Claude가 필요한 도구를 스스로 고른다. 짧은 질문은 바로 답하고, 긴 작업은 단계를 나눠 진행한다.
- 공통: 컴퓨터의 폴더를 Claude에게 열어 주면(작업 폴더) 그 안의 파일을 읽고, 새 파일을 만들고, 정리한다. 폴더를 다루는 일은 Claude 데스크톱 앱이 열려 있어야 한다. 폴더를 고르는 정확한 메뉴 이름과 위치는 단정하지 않는다("입력창 근처의 더하기(+) 버튼이나 폴더 추가 메뉴" 정도까지).
- 공통: 여러 단계로 이루어진 작업 하나를 통째로 맡긴다. 작업 중간 과정이 단계별로 표시되고, 필요한 경우 사용자에게 확인을 요청한다.
- 공통: 결과물은 파일(문서, 표, 요약본 등)로 만들어진다. 작업 폴더를 지정했으면 그 폴더에 생기고, 새 화면에서는 대화 옆에도 표시되어 내려받을 수 있다.
- 공통: 파일을 지우거나 덮어쓰는 작업은 사용자가 확인해야 한다. 원본은 따로 보관해 두라고 안내한다.
- 새 화면의 권한 설정: 입력창 근처에 있다. "수동"(기본값)은 조치 전에 매번 묻고, "자동"은 묻지 않고 계속 진행한다. 초보자에게는 수동을 권한다.
- 새 화면에서 자리를 옮긴 것: 예전 Cowork 작업은 대화 목록(최근 항목)에, Cowork 전역 지침은 설정 > 일반의 Claude 지침에, 웹 검색 스위치는 없어짐(필요할 때 알아서 검색), Research는 입력창의 더하기(+) 버튼에서, 결과 저장 폴더는 설정의 저장소 폴더, 열어 준 폴더 목록은 설정의 신뢰할 수 있는 폴더. 모델 선택과 데스크톱 앱의 Code 탭은 그대로.
- 새 화면에서 긴 작업은 노트북을 닫아도 클라우드에서 계속되고, 휴대폰 앱에서 진행 상황을 볼 수 있다. 단 컴퓨터의 폴더를 쓰는 작업은 데스크톱 앱이 열려 있어야 한다.
- 새 화면에서 당장 안 되는 것(바뀔 수 있음): 시크릿 채팅은 이전 화면으로 열림, 검색에 이전 Cowork 작업이 나오지 않음, 대화 분기 불가.
- Claude Docs(문서), Claude Slides(발표 자료), Claude Design(시각 자료)은 유료 요금제의 베타 기능이다. 이름은 소개하되 사용법을 단계별로 가르치지 않는다.
- 외부 서비스 연결(커넥터), 반복 작업 예약, 내장 브라우저, 컴퓨터 사용은 심화 주제다. 기본 과정에서는 언급만 하거나 생략한다.

## Claude Code 앱

- Claude 데스크톱 앱의 Code 영역에서 쓴다. 터미널(CLI) 버전도 있지만 이 사이트는 앱을 기준으로 한다.
- 흐름: 프로젝트 폴더 선택 → 대화창에 요청 → Claude가 파일을 만들고 수정 → 변경 내용과 실행 결과 확인.
- Claude가 파일을 바꾸거나 명령을 실행하기 전에 허락을 묻는 경우가 있다. 처음에는 하나씩 확인하며 허락하는 쪽을 권한다.
- 앱 안에서 만든 웹페이지를 미리 볼 수 있는 브라우저 화면이 있다. 터미널 화면도 있지만 초보자가 직접 명령을 칠 필요는 없다.
- Claude에게 실행, 미리보기, 오류 확인, Git 저장, GitHub 업로드, 배포까지 말로 요청할 수 있다. 다만 계정 로그인(GitHub, Vercel 등)은 사용자가 직접 브라우저에서 해야 한다.
- 오류 메시지는 복사해서 대화창에 붙여 넣거나, 화면을 캡처해서 붙여 넣으면 Claude가 읽는다.
- 프로젝트마다 `CLAUDE.md` 같은 지침 파일을 둘 수 있다. 이것은 심화 주제다.

## Git · GitHub · Vercel

- Git: 프로젝트의 변경 내용을 기록하는 도구. 게임의 세이브 포인트에 비유한다. 저장 단위를 커밋(commit)이라 부른다.
- GitHub: 프로젝트를 온라인에 보관하고 공유하는 서비스. 보관함 하나를 저장소(Repository)라 부른다. 계정은 무료로 만들 수 있다.
- GitHub에 올리는 일은 Claude Code에 말로 요청할 수 있다. 처음 한 번은 GitHub 로그인 승인이 필요하다.
- Vercel: 웹사이트를 인터넷에 올려 주는 서비스. GitHub 저장소를 연결하면 자동으로 배포된다. 무료 요금제로 시작할 수 있다.
- GitHub에 새 내용을 올리면(push) Vercel이 자동으로 다시 배포한다.
- 환경변수: Vercel 프로젝트 설정의 Environment Variables 메뉴에 등록한다. 등록 후에는 다시 배포해야 반영된다.

## 데이터 저장

- LocalStorage: 브라우저 안에 데이터를 저장하는 작은 보관함. 서버와 회원가입이 필요 없다. 같은 기기의 같은 브라우저에서만 보인다. 브라우저 데이터를 지우면 사라진다.
- Firebase: Google의 앱 개발 플랫폼. 이 사이트의 예제는 Firebase를 기준으로 한다. 사용하는 기능은 Firestore(데이터베이스), Authentication(로그인, Google 로그인 우선), 실시간 구독.
- Supabase: PostgreSQL 기반 서비스. 소개와 비교는 하되 예제 프로젝트에서는 Firebase 하나로 끝까지 간다.
- Firebase 웹 설정값(apiKey 등)은 브라우저에 노출되는 공개 설정값이다. 이것을 숨기는 것이 보안이 아니다. 실제 접근 권한은 보안 규칙(Firestore Security Rules)으로 제한한다.
- 로컬 설정값은 `.env.local`에 두고 Git에 올리지 않는다(`.gitignore`). 배포 환경에서는 Vercel 환경변수에 등록한다.
- 사용자별 데이터는 사용자 ID(uid)를 기준으로 구분한다. 이메일을 핵심 식별자로 쓰지 않는다.
- 역할(교사/관리자, 학생)에 따른 권한은 화면에서 버튼을 숨기는 것으로 끝나지 않는다. 보안 규칙에서 제한해야 한다.
- 학교에서 학생 데이터를 다룰 때는 기관의 개인정보 지침을 확인해야 한다. 예제에서는 가상의 데이터를 쓴다.
