## 이 페이지를 읽는 시점

이 페이지는 데이터베이스나 로그인을 붙인 뒤에 읽는 심화 내용입니다. 아직 붙이지 않았다면 지금 읽지 않아도 됩니다.

환경변수가 무엇인지는 [환경변수란?](/database/environment-variables)에서 먼저 설명합니다. 그 페이지를 읽고 내 컴퓨터에서 데이터베이스 연결이 되는 것을 확인한 다음, 이 페이지로 돌아오세요.

## 이것만 알아두세요

내 컴퓨터에서는 설정값을 프로젝트 폴더 안의 파일에 적어 두고 씁니다. 보통 파일 이름이 `.env.local`입니다.

이 파일은 GitHub에 올라가지 않습니다. 그래서 배포한 사이트에는 설정값이 없는 상태가 됩니다. 같은 값을 Vercel에도 따로 등록해 주어야 합니다.

이 한 가지를 몰라서 헤매는 경우가 아주 많습니다. 내 컴퓨터에서는 잘 되는데 배포 주소에서만 데이터가 저장되지 않는다면, 대부분 이것이 원인입니다.

## 왜 파일은 GitHub에 올라가지 않나요

설정값 파일에는 비밀값이 들어갈 수 있기 때문입니다. GitHub 저장소는 실수로 공개되기 쉬우므로, 처음부터 올리지 않는 것을 기본으로 삼습니다.

그래서 프로젝트에는 이 파일을 제외하는 목록(`.gitignore`)이 들어 있습니다. Claude Code로 만든 프로젝트라면 대부분 이미 포함되어 있습니다.

<Warning>
설정값 파일이 GitHub에 이미 올라가 있지 않은지 한 번 확인하세요. github.com에서 내 저장소를 열어 `.env.local`이 보인다면 올라간 것입니다.

이 경우 Claude에게 저장소에서 제외해 달라고 요청하고, 노출된 값은 해당 서비스에서 새로 발급받는 편이 안전합니다.
</Warning>

## 공개 설정값과 비밀값은 다릅니다

모든 설정값이 비밀번호 같은 것은 아닙니다.

Firebase의 웹 설정값처럼 브라우저에 그대로 실려 나가도록 설계된 값이 있습니다. 이런 값은 숨기는 것이 목적이 아닙니다. 숨겨도 브라우저 개발자 도구에서 다 보입니다.

이런 값을 환경변수로 관리하는 이유는 보안 때문이 아니라, 개발용과 배포용을 나누고 값을 한곳에서 관리하기 위해서입니다.

실제 데이터 접근을 막는 것은 값을 가리는 일이 아니라 서버 쪽 보안 규칙입니다. 이 구분은 [설정값을 숨기면 안전한가요?](/security/hiding-config-is-not-security)에서 자세히 다룹니다.

## 직접 해봅시다

<Steps>
<Step title="내 컴퓨터의 설정값 목록을 확인합니다">
프로젝트 폴더 안의 `.env.local` 파일을 엽니다. 아래처럼 이름과 값이 한 줄씩 적혀 있습니다. 이름은 프로젝트마다 다르므로 파일에 적힌 그대로 씁니다.

```
FIREBASE_API_KEY=여기에-값-입력
FIREBASE_PROJECT_ID=여기에-값-입력
```
</Step>
<Step title="Vercel 프로젝트의 환경변수 설정 메뉴를 엽니다">
내 프로젝트의 설정 화면에 환경변수(Environment Variables)를 등록하는 메뉴가 있습니다.
</Step>
<Step title="이름과 값을 하나씩 등록합니다">
이름을 정확히 똑같이 씁니다. 대소문자와 밑줄까지 한 글자도 달라지면 안 됩니다.

값을 붙여 넣을 때 앞뒤에 빈칸이나 따옴표가 섞여 들어가지 않게 주의하세요. 이 실수가 가장 흔합니다.
</Step>
<Step title="어느 환경에 적용할지 고릅니다">
운영, 미리보기 등 적용 범위를 고르는 항목이 있습니다. 어떤 것인지 모르겠다면 전부 선택해 두면 됩니다.
</Step>
<Step title="등록을 마친 뒤 다시 배포합니다">
환경변수는 등록만 하면 반영되지 않습니다. 등록 이후에 새로 만들어지는 배포부터 적용됩니다.

Vercel의 배포 목록에서 다시 배포하거나, GitHub에 새 내용을 올려 새 배포를 만듭니다.
</Step>
</Steps>

## 이렇게 나오면 성공입니다

<Success>
다시 배포한 뒤 배포 주소를 열면, 데이터가 저장되거나 불러와집니다.

브라우저 개발자 도구의 콘솔 화면에 설정값이 없다는 뜻의 오류가 더 이상 보이지 않습니다.

Firebase 콘솔의 데이터베이스 화면을 열어 실제로 데이터가 들어왔는지도 함께 확인하세요. 화면에만 남고 저장되지 않는 경우가 있습니다.
</Success>

## 잘 안 된다면

<Troubleshoot>
<Problem title="등록했는데도 연결되지 않아요">
가장 흔한 원인은 다시 배포하지 않은 것과 이름 오타입니다. [환경변수를 설정했는데 연결되지 않아요](/troubleshooting/env-vars-not-working)에서 순서대로 확인하세요.
</Problem>
<Problem title="어떤 값을 등록해야 하는지 모르겠어요">
Claude Code 대화창에서 물어보면 됩니다. 아래 프롬프트를 쓰세요. 값 자체를 대화창에 붙여 넣을 필요는 없습니다.
</Problem>
</Troubleshoot>

## 값이 바뀌면 다시 등록합니다

Firebase 프로젝트를 새로 만들거나 설정을 바꾸면 값도 함께 바뀝니다. 이때는 두 곳을 모두 고쳐야 합니다.

내 컴퓨터의 `.env.local`과 Vercel의 환경변수 두 곳입니다. 한쪽만 고치면 내 컴퓨터와 배포 사이트가 서로 다른 곳을 보게 됩니다. 이 상태는 원인을 찾기가 특히 어렵습니다.

## Claude에게 이렇게 말해보세요

<PromptBox>
이 프로젝트가 실행될 때 필요한 환경변수의 이름을 전부 알려 줘. 각 이름이 어떤 용도인지도 한 줄씩 설명해 줘. 값은 보여주지 말고 이름만 정리해 줘. 코드는 바꾸지 마.
</PromptBox>
