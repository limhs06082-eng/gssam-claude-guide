## 이 페이지를 읽는 시점

이 페이지는 데이터베이스를 붙인 뒤에 읽는 심화 내용입니다. 아직 붙이지 않았다면 [환경변수란?](/database/environment-variables)과 [첫 데이터 저장하기](/database/save-first-data)를 먼저 보고 오세요.

로그인까지 붙인 앱이라면 [Google 로그인 붙이기](/auth/add-google-login)와 [배포 후 로그인 테스트하기](/deployment/login-after-deploy)도 함께 확인합니다.

## 이것만 알아두세요

배포가 성공했다는 것은 화면이 열린다는 뜻일 뿐입니다. 데이터가 실제로 저장되는지는 따로 확인해야 합니다.

확인 방법은 간단합니다. 배포 주소에서 데이터를 하나 넣어 보고, 그 데이터가 데이터베이스 화면에도 보이는지 눈으로 확인하는 것입니다.

내 컴퓨터에서 확인한 것으로 대신하지 마세요. 두 곳은 서로 다른 설정으로 돌아가기 때문에, 한쪽이 된다고 다른 쪽도 된다고 볼 수 없습니다.

## 직접 해봅시다

<Steps>
<Step title="배포 주소를 새 창에서 엽니다">
내 컴퓨터에서 실행 중인 화면이 아니라, 배포된 주소를 열어야 합니다. 두 화면이 비슷하게 생겨서 헷갈리기 쉽습니다. 주소창을 한 번 확인하세요.
</Step>
<Step title="알아보기 쉬운 데이터를 하나 넣습니다">
"배포 확인 테스트"처럼 나중에 찾기 쉬운 내용을 넣습니다. 실제 학생 이름이나 개인정보는 쓰지 않습니다.
</Step>
<Step title="화면을 새로고침합니다">
새로고침한 뒤에도 방금 넣은 내용이 남아 있어야 합니다. 사라진다면 저장이 되지 않은 것입니다.
</Step>
<Step title="데이터베이스 화면에서 직접 확인합니다">
Firebase 콘솔의 데이터베이스 화면을 엽니다. 방금 넣은 내용이 그대로 들어와 있으면 연결이 잘 된 것입니다.

여기까지 확인해야 확실합니다. 화면에만 남아 있고 데이터베이스에는 없는 경우도 있기 때문입니다.
</Step>
<Step title="다른 기기에서 같은 주소를 엽니다">
휴대폰으로 배포 주소를 열어 봅니다. 컴퓨터에서 넣은 내용이 보이면 여러 기기에서 같은 데이터를 쓰고 있다는 뜻입니다.

로그인이 있는 앱이라면 같은 계정으로 로그인한 뒤에 확인합니다.
</Step>
<Step title="확인용 데이터를 지웁니다">
테스트로 넣은 데이터는 정리해 둡니다. 다음에 볼 때 실제 데이터와 섞이지 않게 하기 위해서입니다.
</Step>
</Steps>

## 개발용과 배포용을 같은 곳에 쓰고 있나요

내 컴퓨터에서 연습하며 넣은 데이터와, 실제로 쓰는 데이터가 같은 데이터베이스에 섞이는 일이 자주 생깁니다.

혼자 연습하는 단계에서는 하나로 써도 괜찮습니다. 다만 다음 두 가지는 지키는 편이 좋습니다.

- 연습용 데이터에는 알아보기 쉬운 이름을 붙이고, 확인이 끝나면 지웁니다.
- 실제로 사람들이 쓰기 시작하는 앱이라면, 연습용과 실제용을 나누는 방법을 Claude에게 물어봅니다.

특히 삭제 기능을 시험할 때 조심하세요. 연습으로 지운 것이 실제 데이터일 수 있습니다. 지우기 전에 무엇을 지우는지 한 번 확인하는 습관을 들이면 좋습니다.

## Claude에게 이렇게 말해보세요

<PromptBox>
배포한 사이트에서는 데이터가 저장되지 않고, 내 컴퓨터에서 실행할 때는 저장돼. 브라우저 콘솔에 아래 내용이 나왔어.

(여기에 콘솔에 나온 내용을 붙여 넣습니다)

배포 환경에서만 실패하는 원인을 찾아 줘. 내가 Vercel이나 Firebase 화면에서 직접 확인해야 하는 설정이 있으면 그것부터 알려 줘. 기존 기능은 바꾸지 마.
</PromptBox>

## 이렇게 나오면 성공입니다

<Success>
배포 주소에서 넣은 데이터가 새로고침 후에도 남아 있고, Firebase 콘솔의 데이터베이스 화면에서도 같은 내용이 보입니다.

휴대폰으로 열었을 때도 같은 데이터가 나타납니다.

여기까지 확인되면 배포 환경과 데이터베이스가 제대로 연결된 것입니다. 다음은 보안 규칙 차례입니다.
</Success>

## 확인이 끝나면 보안 규칙을 봅니다

<Warning>
연결이 잘 되는 것과 안전한 것은 다릅니다. 개발 중 편하게 쓰려고 데이터베이스를 누구나 읽고 쓸 수 있게 열어 두었다면, 배포 전에 반드시 잠가야 합니다.

주소를 아는 사람은 누구나 배포 사이트에 들어올 수 있습니다. [보안 규칙이란?](/security/what-are-security-rules)에서 확인하세요.
</Warning>
