## 이것만 알아두세요

Firebase 설정값은 코드 안에 직접 쓰지 않고 별도의 파일에 모아 둡니다. 그 파일 이름이 보통 `.env.local`입니다.

이렇게 관리하는 값을 환경변수라고 부릅니다. 값이 여러 곳에 흩어지지 않고, 내 컴퓨터용과 배포용을 나눠 쓸 수 있습니다.

## 쉽게 생각하면

<Analogy>
가정통신문을 만들 때, 학년과 반 이름을 문서 안에 직접 타이핑해 넣으면 반마다 문서를 새로 고쳐야 합니다.

대신 첫 장에 "학년: ___, 반: ___" 칸을 만들어 두고 본문은 그 칸을 가리키게 하면, 칸만 바꿔서 여러 반에 쓸 수 있습니다.

환경변수가 그 칸입니다. 값이 바뀌어도 본문은 그대로 둡니다.
</Analogy>

## 파일은 이렇게 생겼습니다

프로젝트 폴더 안에 `.env.local` 파일이 있습니다. 안을 열어 보면 이름과 값이 한 줄씩 적혀 있습니다.

```
FIREBASE_API_KEY=여기에-값-입력
FIREBASE_PROJECT_ID=여기에-값-입력
```

이름은 프로젝트마다 다릅니다. Claude가 만들어 준 파일에 적힌 이름을 그대로 쓰고, 등호 뒤의 자리에 Firebase 콘솔에서 확인한 값을 붙여 넣습니다.

값 앞뒤에 빈칸이나 따옴표가 섞이지 않게 주의하세요. 연결이 안 되는 원인 중 가장 흔한 것이 이 실수입니다.

## GitHub에 올라가지 않게 합니다

이 파일은 GitHub에 올리지 않습니다. 프로젝트에는 올리지 않을 파일 목록(`.gitignore`)이 있고, 거기에 `.env.local`이 들어 있어야 합니다.

Claude Code로 만든 프로젝트라면 대부분 이미 들어 있습니다. 확인하려면 이렇게 물어보면 됩니다.

<PromptBox>
이 프로젝트의 .gitignore에 .env.local이 들어 있는지 확인해 줘. 없으면 추가해 줘.

그리고 지금까지 GitHub에 올린 내용 중에 설정값 파일이 포함된 적이 있는지도 확인해 줘. 값 자체는 화면에 보여주지 말고 결과만 알려 줘.
</PromptBox>

<Warning>
이미 올라가 있다면 저장소에서 제외하는 것만으로 끝나지 않습니다. 지난 기록에 값이 남아 있을 수 있습니다.

비밀값이 포함되어 있었다면 해당 서비스에서 새로 발급받는 편이 안전합니다.
</Warning>

## 여기서 오해하기 쉬운 부분

"숨기니까 안전해졌다"고 생각하기 쉽습니다. 그런데 Firebase 웹 설정값은 조금 다릅니다.

이 값들은 브라우저에서 사용하도록 설계된 값입니다. 앱이 동작하려면 브라우저까지 실려 나가야 합니다. 그래서 누군가 마음먹고 찾아보면 개발자 도구에서 볼 수 있습니다.

그렇다고 아무 데나 적어도 된다는 뜻은 아닙니다. 정리하면 이렇습니다.

**환경변수로 관리하는 이유는 관리 편의 때문입니다.** 값을 한곳에 모으고, 연습용과 실제용을 나누고, 나중에 바꿀 때 한 줄만 고치면 되기 때문입니다.

**실제로 접근을 막는 것은 보안 규칙입니다.** 누가 어떤 데이터를 읽고 쓸 수 있는지는 Firebase 쪽에서 정합니다. 설정값을 가리는 것과는 별개의 일입니다.

이 구분은 [설정값을 숨기면 안전한가요?](/security/hiding-config-is-not-security)에서 자세히 다룹니다. 지금은 "설정값을 숨겼다고 데이터가 보호되는 것은 아니다"만 기억하면 됩니다.

## 진짜 숨겨야 하는 값도 있습니다

모든 설정값이 공개용은 아닙니다.

관리자 권한을 가진 열쇠나, 다른 서비스의 유료 API 키처럼 브라우저에 나가면 안 되는 값이 있습니다. 이런 값은 절대 코드나 브라우저 쪽에 두지 않습니다.

지금 단계에서는 그런 값을 쓸 일이 없습니다. 나중에 Claude가 어떤 값을 요구할 때, 브라우저에서 쓰는 값인지 아닌지 물어보는 습관을 들이면 됩니다.

## 배포할 때는 따로 등록합니다

`.env.local`은 GitHub에 올라가지 않으므로, 배포한 사이트에는 설정값이 없는 상태가 됩니다.

그래서 배포 서비스에도 같은 값을 따로 등록해야 합니다. 방법은 [Vercel에 환경변수 등록하기](/deployment/environment-variables-on-vercel)에 있습니다. 배포는 아직 하지 않아도 되니, 그때 다시 보면 됩니다.

## 잘 안 된다면

<Troubleshoot>
<Problem title=".env.local 파일이 안 보여요">
점으로 시작하는 파일은 탐색기에서 숨겨져 있을 수 있습니다. Claude Code 대화창에서 "프로젝트에 .env.local이 있는지 확인해 줘"라고 물어보는 편이 빠릅니다.
</Problem>
<Problem title="값을 넣었는데 연결이 안 돼요">
앱을 완전히 껐다 다시 실행하세요. 설정값은 실행할 때 한 번 읽습니다. 다른 원인은 [환경변수를 설정했는데 연결되지 않아요](/troubleshooting/env-vars-not-working)에 정리되어 있습니다.
</Problem>
</Troubleshoot>

지금은 값을 다룰 때 한 가지 습관을 지킵니다. 값은 파일에 직접 넣고, Claude에게는 "그 파일의 어느 이름에 넣으면 되는지"만 묻습니다.

공개 설정값이라도 이 습관을 들여 두면, 나중에 진짜 비밀값을 다룰 때 실수하지 않습니다.
</TeacherTip>
