## 이것만 알아두세요

데이터베이스는 더 좋은 저장 방법이 아니라, 필요할 때 쓰는 저장 방법입니다.

혼자 한 대의 기기에서 쓰는 앱이라면 지금 그대로가 낫습니다. 붙이는 순간 관리할 것이 늘어나기 때문입니다.

## 다섯 가지 상황

아래 중 하나라도 해당하면 데이터베이스를 검토합니다. 하나도 없다면 [LocalStorage](/storage/what-is-localstorage)로 충분합니다.

1. **컴퓨터와 휴대폰에서 같은 데이터를 봐야 합니다.** 학교 컴퓨터에서 적은 것을 집에서도 봐야 하는 경우입니다.
2. **여러 사람이 같은 데이터를 봐야 합니다.** 학년 선생님들이 함께 쓰는 준비물 목록 같은 것입니다.
3. **학생과 교사가 데이터를 주고받아야 합니다.** 한쪽이 넣은 내용을 다른 쪽이 확인하는 구조입니다.
4. **사용자마다 다른 데이터를 저장해야 합니다.** 이 경우에는 로그인도 함께 필요합니다.
5. **오래 남겨야 하는 기록입니다.** 브라우저 데이터를 지우면 사라지면 곤란한 자료입니다.

[어떤 앱까지 LocalStorage로 충분할까요?](/storage/is-localstorage-enough)의 여섯 개 질문과 같은 이야기입니다. 그 페이지에서 두 번째 질문 이후에 걸렸다면 여기가 맞습니다.

## 이런 앱은 필요합니다

| 만들려는 앱 | 왜 필요한가요 |
| --- | --- |
| 학교와 집에서 같이 쓰는 업무 목록 | 기기가 바뀌어도 데이터가 따라와야 합니다 |
| 학년 선생님들이 함께 쓰는 준비물 목록 | 여러 사람이 같은 내용을 봐야 합니다 |
| 학생이 제출하고 교사가 확인하는 앱 | 서로 다른 기기의 데이터를 봐야 합니다 |
| 실시간 학급 상태판 | 한쪽의 변경이 다른 쪽에 보여야 합니다 |
| 학기 내내 쌓이는 활동 기록 | 오래 보관해야 합니다 |

## 이런 앱은 필요하지 않습니다

| 만들려는 앱 | 왜 필요 없나요 |
| --- | --- |
| 수업용 타이머 | 저장할 것이 거의 없습니다 |
| 무작위 발표자 뽑기 | 매번 새로 시작해도 됩니다 |
| 나만 쓰는 메모장 | 내 기기 한 대면 충분합니다 |
| 교실 컴퓨터의 자리배치 저장 | 그 컴퓨터에서만 씁니다 |
| 소개용 한 페이지 홈페이지 | 사용자가 입력하는 데이터가 없습니다 |

## 애매할 때는 이렇게 판단합니다

표를 봐도 헷갈리는 경우가 있습니다. 그럴 때 도움이 되는 질문이 두 개 있습니다.

**"이 화면을 다른 사람에게 보여 줄 일이 있습니까?"** 주소를 알려 줬을 때 상대가 나와 같은 내용을 봐야 한다면 데이터베이스입니다. 각자 자기 목록을 만들어 쓰면 되는 앱이라면 아닙니다.

**"이 데이터가 사라지면 다시 만들 수 있습니까?"** 30분이면 다시 채울 수 있는 내용이라면 급하지 않습니다. 복구할 수 없는 기록이라면 처음부터 데이터베이스로 갑니다.

## 나중에 옮겨도 됩니다

지금 판단이 서지 않는다면 먼저 완성하는 쪽을 선택하세요.

앱을 만들어서 몇 번 써 봐야 무엇이 부족한지 알게 됩니다. 처음부터 데이터베이스를 준비하다가 앱을 끝내지 못하는 것이 가장 아쉬운 결과입니다.

옮기는 작업도 Claude Code에 요청하면 됩니다. 이때 중요한 것은 지금 상태를 먼저 설명하는 것입니다.

## 옮길 때는 이렇게 말합니다

<PromptBox>
현재는 교사용 체크리스트가 LocalStorage에 저장되고 있어. 항목을 추가하고 체크하고 삭제할 수 있어.

이제 학교 컴퓨터와 집 노트북에서 같은 목록을 보고 싶어. 나 혼자 쓰는 앱이고 로그인은 아직 필요 없어. 실시간으로 같이 보는 기능도 지금은 필요 없어.

Firebase를 사용해서 구현해 줘. 먼저 현재 프로젝트 구조를 확인하고 어떻게 바꿀지 설명한 다음 작업해 줘. 기존 체크리스트 기능과 디자인은 변경하지 마.
</PromptBox>

이 요청에는 다섯 가지가 들어 있습니다. 지금 어떻게 동작하는지, 무엇을 바꾸고 싶은지, 누가 쓰는지, 아직 필요 없는 것은 무엇인지, 그리고 기존 기능을 지켜 달라는 것입니다.

"필요 없다"고 미리 말하는 부분이 특히 중요합니다. 그 말이 없으면 로그인과 실시간 기능까지 한꺼번에 붙는 경우가 있습니다. 그러면 무엇 때문에 오류가 났는지 찾기 어려워집니다.

<Note>
바로 요청하지 말고 이 과정을 순서대로 따라오세요. 다음 페이지부터 Firebase 보관함을 만들고 한 단계씩 붙입니다. 위 요청은 준비가 끝난 뒤에 쓰는 것입니다.
</Note>

## G쌤 팁

<TeacherTip>
저는 "나중에 여러 선생님이 쓸 수도 있으니까"라는 생각으로 첫 앱부터 데이터베이스를 붙였습니다. 결국 그 앱은 저 혼자 썼습니다.

반대로 정말 같이 쓰게 된 앱은, 옆 반 선생님이 "그거 나도 쓰고 싶은데"라고 말한 다음에 옮겼습니다. 그때는 무엇이 필요한지 분명해서 요청도 훨씬 정확했습니다.

필요해진 다음에 붙이세요. 옮기는 데 걸리는 시간보다, 필요하지도 않은 기능을 관리하는 시간이 훨씬 깁니다.
</TeacherTip>
