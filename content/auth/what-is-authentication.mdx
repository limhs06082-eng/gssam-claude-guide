## 이것만 알아두세요

인증은 "지금 들어온 사람이 누구인지 확인하는 것"입니다. 영어로는 Authentication이라고 합니다.

그리고 한 가지만 기억하면 됩니다. 비밀번호를 받아서 확인하는 장치를 직접 만들지 않습니다. 이미 검증된 로그인 서비스를 씁니다.

## 쉽게 생각하면

<Analogy>
학교 정문에서 방문증을 받는 절차와 같습니다.

경비실에서는 신분증을 확인하고 "이 사람은 김하늘 선생님이 맞다"는 것만 판단합니다. 그 사람이 교장실에 들어가도 되는지, 학생부 서류를 볼 수 있는지는 정문에서 정하지 않습니다.

인증도 딱 여기까지입니다. 누구인지 확인해 주는 것이 전부입니다. 무엇을 할 수 있는지는 그다음 문제입니다.
</Analogy>

## 앱 입장에서 인증이란

앱은 브라우저에서 들어오는 요청이 누구의 것인지 원래 알지 못합니다.

인증을 붙이면 앱이 이렇게 말할 수 있게 됩니다. "지금 이 화면을 보고 있는 사람은 어제 왔던 그 사람과 같은 사람이다."

이 한 문장이 만들어지면 사용자마다 다른 데이터를 보여줄 수 있습니다. 인증이 먼저이고, 사용자별 데이터는 그 위에 얹힙니다.

## 비밀번호 시스템을 직접 만들지 않습니다

<Warning title="꼭 지켜야 할 원칙">
로그인 기능을 만들 때 다음을 직접 구현하지 않습니다.

- 비밀번호를 받아서 데이터베이스에 저장하는 기능
- 직접 고안한 암호화 방식
- 직접 만든 로그인 유지 방식

Claude에게 요청하면 이런 코드도 만들어 줍니다. 만들 수 있다는 것과 써도 된다는 것은 다릅니다.
</Warning>

비밀번호를 다루는 일은 생각보다 훨씬 까다롭습니다. 저장할 때 어떻게 바꿔서 넣을지, 여러 번 틀렸을 때 어떻게 막을지, 비밀번호를 잊었을 때 어떻게 되돌릴지, 로그인 상태를 얼마나 유지할지를 모두 제대로 처리해야 합니다.

하나만 잘못 만들어도 사용자의 비밀번호가 통째로 새어 나갈 수 있습니다. 그리고 사람들은 여러 서비스에서 같은 비밀번호를 쓰는 경우가 많아서, 피해가 그 앱 하나로 끝나지 않습니다.

그래서 이 부분은 이미 오랫동안 검증된 서비스에 맡깁니다. Firebase Authentication이나 Supabase Auth 같은 것들입니다. 이 사이트의 예제는 Firebase Authentication을 사용합니다.

## Google 로그인을 먼저 쓰는 이유

Firebase Authentication은 여러 로그인 방식을 제공하는데, 이 과정에서는 Google 로그인을 씁니다.

**비밀번호를 아예 다루지 않습니다.** 비밀번호 입력창 자체가 앱에 없습니다. 사용자는 Google 화면에서 계정을 고르고 돌아옵니다.

**학교에서 이미 쓰는 계정입니다.** 새 계정을 만들라고 안내할 필요가 없습니다.

**비밀번호 찾기 기능을 만들지 않아도 됩니다.** 잊어버렸다면 Google에서 해결합니다.

<Note>
Google 계정이 없는 사용자가 대상이라면 다른 방식을 검토해야 합니다. 그런 경우에도 직접 만들지 말고, Firebase Authentication이 제공하는 다른 로그인 방식 중에서 고르세요.
</Note>

## 로그인에는 여섯 가지 상태가 있습니다

로그인 버튼 하나만 있으면 될 것 같지만, 실제로는 다음 상태를 모두 처리해야 합니다.

- 아직 로그인하지 않은 상태
- 로그인 창이 열려 있는 중간 상태
- 로그인에 성공한 상태
- 로그인에 실패한 상태
- 로그아웃한 상태
- 창을 닫았다 다시 열었을 때 로그인이 유지되는 상태

마지막 항목이 특히 자주 빠집니다. 새로고침할 때마다 로그인 화면이 잠깐 나타났다 사라지는 앱은 대부분 이 처리가 없는 경우입니다.

실패 상태도 자주 빠집니다. 사용자가 계정 선택 창을 그냥 닫는 경우가 있는데, 이때 화면이 멈춰 있으면 무엇이 잘못됐는지 알 수 없습니다.

Claude에게 요청할 때 이 목록을 그대로 붙여 넣으면 빠뜨리지 않습니다. 다음 페이지에서 실제 요청 문장을 함께 만듭니다.

## 로그인 서비스가 대신 해 주는 일

Firebase Authentication을 쓰면 다음을 직접 만들지 않아도 됩니다.

- 사용자가 누구인지 확인하는 절차 전체
- 로그인 상태를 안전하게 유지하는 방법
- 사용자 목록 관리. 누가 가입했는지는 Firebase 콘솔에서 볼 수 있습니다.
- 계정을 지우거나 사용을 막는 기능

내가 하는 일은 로그인 버튼과 로그아웃 버튼을 화면에 놓고, 로그인 결과를 받아서 화면을 다르게 보여주는 것뿐입니다.

## 인증만으로는 끝나지 않습니다

인증은 "누구인가"까지만 답합니다. "무엇을 할 수 있는가"는 권한이라는 다른 문제입니다.

로그인한 사람이라고 해서 모든 데이터를 봐도 되는 것은 아닙니다. 이 구분은 [권한(Authorization)이란?](/auth/what-is-authorization)에서 자세히 다룹니다.
