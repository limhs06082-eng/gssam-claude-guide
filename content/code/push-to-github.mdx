## 이것만 알아두세요

GitHub에 올리는 일도 말로 부탁합니다. 명령어를 칠 필요가 없습니다.

처음 한 번만 GitHub 로그인 승인이 필요하고, 그 뒤로는 "변경 내용을 GitHub에 저장해 줘" 한마디면 됩니다.

## 올리기 전에 확인할 것

<Warning>
파일 안에 남에게 보이면 안 되는 것이 있는지 먼저 봅니다.

비밀번호, 개인 연락처, 학생 이름과 같은 정보가 들어 있다면 올리기 전에 지우거나 가상의 값으로 바꿉니다.

한 번 공개 저장소에 올라간 내용은 나중에 지워도 기록에 남을 수 있습니다.
</Warning>

## 직접 해봅시다

<Steps>
<Step title="GitHub 계정에 로그인해 둡니다">
브라우저에서 github.com에 로그인한 상태로 둡니다. 계정이 없다면 [GitHub란?](/code/what-is-github)을 먼저 보세요.
</Step>
<Step title="지금 상태가 잘 되는지 확인합니다">
새로고침해서 화면과 버튼이 정상인지 봅니다. 잘 되는 상태를 올리는 것이 좋습니다.
</Step>
<Step title="아래 문장을 보냅니다">
저장소 이름과 공개 여부를 함께 적어 주면 되묻는 과정이 줄어듭니다.
</Step>
<Step title="브라우저에서 GitHub 로그인 승인을 합니다">
승인 화면이 열리면 내용을 읽고 승인합니다. 이 단계는 처음 한 번만 필요합니다.

비밀번호를 대화창에 적지 마세요. 로그인은 브라우저에서 직접 합니다.
</Step>
<Step title="허락을 묻는 창이 뜨면 읽고 허락합니다">
파일을 올리는 작업입니다.
</Step>
<Step title="저장소 주소를 받아 열어 봅니다">
작업이 끝나면 주소를 알려 줍니다. 브라우저에서 열어 파일이 올라갔는지 눈으로 확인합니다.
</Step>
</Steps>

## 이렇게 말해보세요

<PromptBox>
이 프로젝트를 GitHub에 올려 줘. 저장소 이름은 my-first-site로 하고, 비공개로 만들어 줘.

올리기 전에 비밀번호나 개인정보처럼 공개되면 안 되는 내용이 파일에 있는지 먼저 확인해 줘. 다 끝나면 저장소 주소를 알려 줘.
</PromptBox>

## 이렇게 나오면 성공입니다

<Success>
저장소 주소를 받고, 브라우저로 열면 내 파일 목록이 보입니다.

파일 이름이 내 컴퓨터 폴더에 있는 것과 같으면 잘 올라간 것입니다.

이제 컴퓨터가 고장 나도 프로젝트는 남아 있습니다.
</Success>

## 다음부터는 한 문장이면 됩니다

한 번 올려 두면 그 뒤는 훨씬 간단합니다.

무언가를 고친 뒤에 이렇게 말하면 됩니다. "변경 내용을 GitHub에 저장해 줘. 설명은 '모바일 화면 정리'로 남겨 줘."

이 작업을 올린다는 뜻으로 푸시(push)라고 부릅니다. 용어를 몰라도 쓰는 데 지장은 없습니다.

작업이 한 단계 끝날 때마다 올리는 습관을 들이세요. 그러면 GitHub의 내용이 항상 최신 상태로 유지됩니다.

<Note>
GitHub에 올려 두면 인터넷에 공개할 준비가 끝난 셈입니다.

배포 서비스는 이 저장소를 가져가 웹사이트로 만들어 줍니다. 다음은 [배포란?](/deployment/what-is-deployment)입니다.
</Note>

## 잘 안 된다면

<Troubleshoot>
<Problem title="로그인 승인 화면이 안 뜨거나 실패해요">
브라우저에서 github.com에 먼저 로그인한 뒤 다시 요청해 보세요. 그래도 안 되면 [GitHub에 올라가지 않아요](/troubleshooting/github-push-fails)를 보세요.
</Problem>
<Problem title="같은 이름의 저장소가 이미 있다고 나와요">
"저장소 이름을 my-first-site-2로 바꿔서 다시 올려 줘"라고 다른 이름을 알려 주세요.
</Problem>
<Problem title="일부 파일이 안 올라갔어요">
올리지 않도록 지정된 파일일 수 있습니다. "어떤 파일이 올라가지 않았고 왜 그런지 알려 줘"라고 물어보세요.
</Problem>
</Troubleshoot>
