## 무엇을 만드나요

모둠별 활동 상태를 함께 보는 화면을 만듭니다. 교실 앞 화면에 모둠 카드가 나열되고, 각 모둠이 자기 기기에서 상태를 바꾸면 앞 화면이 새로고침 없이 바뀝니다.

상태는 세 가지면 충분합니다. 하는 중, 도움 필요, 완료입니다. 교사는 앞 화면만 보고도 어느 모둠에 가야 하는지 알 수 있습니다.

앞 프로젝트와 다른 점은 여러 사람이 같은 데이터를 동시에 본다는 것입니다.

## 생각하기

| 질문 | 이 앱의 답 | 그래서 |
| --- | --- | --- |
| 데이터를 저장해야 합니까? | 예 | 저장 기능이 필요합니다 |
| 현재 기기에서만 써도 됩니까? | 아니요 | 데이터베이스가 필요합니다 |
| 여러 사람이 같은 데이터를 봐야 합니까? | 예 | 데이터베이스가 필요합니다 |
| 변경이 바로바로 보여야 합니까? | 예 | 실시간 동기화가 필요합니다 |
| 사용자를 구분해야 합니까? | 아니요 | 로그인을 넣지 않습니다 |
| 사용자마다 할 수 있는 일이 다릅니까? | 아니요 | 권한 관리를 넣지 않습니다 |

네 번째 질문에서 실시간이 필요하다는 답이 나왔습니다. 모둠이 상태를 바꿨는데 교사가 새로고침을 눌러야 보인다면 쓸모가 없기 때문입니다. 실시간이 정말 필요한 경우와 아닌 경우의 구분은 [실시간 기능이 필요 없는 경우](/realtime/when-not-to-use-realtime)에 정리되어 있습니다.

다섯 번째는 "아니요"로 둡니다. 한 차시 수업 동안 교실 안에서만 쓰는 화면이라서, 로그인을 붙이면 수업 시간 대부분을 로그인하는 데 쓰게 됩니다.

대신 로그인을 넣지 않기로 한 대가를 알고 시작합니다. 주소를 아는 사람은 누구나 상태를 바꿀 수 있습니다.

그래서 이 앱에는 학생 이름을 넣지 않습니다. 모둠 번호나 모둠 이름만 씁니다. [최소한의 데이터만 저장하기](/security/store-minimal-data)의 원칙을 그대로 적용하는 것입니다.

## 기획하기

누가 쓰나요. 교사와 학생이 함께 씁니다. 교사는 앞 화면을 띄워 두고, 학생은 모둠 기기에서 자기 모둠 카드만 누릅니다.

무엇을 할 수 있어야 하나요. 모둠 상태를 세 가지 중 하나로 바꾸고, 전체 상태를 한 번에 초기화합니다.

화면에 무엇이 보여야 하나요. 모둠 카드가 격자로 나열되고, 상태에 따라 카드 색이 다릅니다. 도움이 필요한 모둠이 멀리서도 바로 눈에 들어와야 합니다.

모둠 수는 처음부터 정해 두는 편이 간단합니다. 여섯 모둠으로 시작하고, 나중에 개수를 바꿀 수 있게 하면 됩니다.

## Claude에게 요청하기

[Firebase 프로젝트 만들기](/database/create-firebase-project)와 [환경변수란?](/database/environment-variables)까지 준비한 뒤 요청합니다. 앞 프로젝트에서 만든 Firebase 프로젝트를 그대로 써도 됩니다.

<PromptBox>
학급 활동 상태판 웹앱을 만들어 줘. 지금은 빈 폴더야.

수업 중에 모둠별 진행 상태를 함께 보는 화면이야. 모둠 카드가 여섯 개 있고, 각 카드는 하는 중, 도움 필요, 완료 중 하나의 상태를 가져. 카드를 누르면 상태가 바뀌어.

교사는 교실 앞 화면에 이 화면을 띄워 두고, 학생은 모둠 태블릿에서 같은 주소를 열어. 한 모둠이 상태를 바꾸면 다른 모든 화면에 새로고침 없이 바로 반영되어야 해.

학생 이름은 저장하지 않아. 모둠 번호와 상태만 저장해. 로그인은 필요 없어.

Firebase를 사용하고 실시간으로 반영되게 해 줘. 설정값은 환경변수로 관리해 줘. 전체 상태를 처음으로 되돌리는 버튼도 넣어 줘.

먼저 어떤 데이터를 어떤 구조로 저장할지 설명한 다음 작업해 줘.
</PromptBox>

"어떤 데이터를 어떤 구조로 저장할지 먼저 설명해 줘"는 데이터가 들어가는 앱에서 항상 붙이면 좋은 문장입니다. 계획 단계에서 학생 이름 같은 항목이 들어 있으면 그때 빼면 됩니다.

## 실행하고 확인하기

실행한 뒤에는 브라우저 창을 두 개 띄워 놓고 확인합니다. 방법은 [여러 브라우저에서 테스트하기](/realtime/test-in-multiple-browsers)에 있습니다.

<Success>
창 두 개를 나란히 놓고 한쪽에서 카드를 누르면, 다른 쪽 화면의 카드도 곧바로 같이 바뀝니다. 새로고침을 누르지 않아도 됩니다.
</Success>

확인할 것이 네 가지입니다.

- 창 두 개에서 서로 다른 카드를 동시에 눌러도 둘 다 반영됩니까?
- 창을 여러 개 열었다 닫아도 화면이 느려지거나 멈추지 않습니까?
- 인터넷이 잠깐 끊겼다 돌아오면 상태가 다시 맞춰집니까?
- 휴대폰 화면에서도 카드가 누르기 좋은 크기입니까?

## 수정하기

교실에서 쓰려면 앞 화면과 학생 화면의 역할이 조금 달라야 합니다.

<PromptBox>
교실 앞 화면에 띄우는 용도의 보기 전용 화면을 하나 더 만들어 줘. 이 화면에서는 카드를 눌러도 상태가 바뀌지 않고 크게 보여 주기만 하면 돼.

도움 필요 상태인 모둠이 눈에 확 띄게 표시해 줘. 기존 화면과 기능은 그대로 두고 추가만 해 줘.
</PromptBox>

</Warning>

## 더 해볼 것

- 모둠 개수를 화면에서 바꿀 수 있게 하기.
- 상태 종류를 수업에 맞게 바꾸기. 예를 들어 읽는 중, 쓰는 중, 발표 준비 완료로 바꿉니다.
- 도움 필요 상태가 얼마나 오래 지속되는지 시간 표시하기.
- 다른 수업 활용 아이디어는 [학교 수업에서 활용하기](/realtime/classroom-uses)에 있습니다.
- 학생마다 다른 화면을 보여야 한다면 [교사와 학생 역할이 다른 앱](/projects/teacher-student-app)으로 갑니다.

## G쌤 팁

<TeacherTip>
실시간 앱은 반드시 수업 전에 교실 기기로 한 번 열어 보시기 바랍니다. 학교 네트워크에서 잘 되는지, 태블릿 화면에서 카드가 누를 만한 크기인지는 실제로 열어 봐야 압니다.

수업에서 처음 쓸 때는 규칙을 먼저 정해 주세요. 자기 모둠 카드만 누른다는 약속 하나면 대부분 정리됩니다. 기술로 막지 않고 약속으로 해결할 수 있는 부분입니다.

그리고 앞 화면용 보기 전용 주소를 따로 만들어 두면 훨씬 편합니다. 앞 화면에서 실수로 카드를 눌러 상태가 바뀌는 일이 사라집니다.
</TeacherTip>
