## 이것만 알아두세요

기본 과정에서는 Firebase의 두 가지만 썼습니다. 데이터를 저장하는 Firestore와 로그인을 담당하는 Authentication입니다.

Firebase에는 그 외에도 여러 기능이 있습니다. 전부 알 필요는 없고, 필요해질 때 하나씩 찾아보면 됩니다.

## 쉽게 생각하면

<Analogy>
학교의 여러 실을 생각해 보세요.

교실만 있으면 수업은 됩니다. 실험을 하려면 과학실이 필요하고, 짐을 보관하려면 창고가 필요합니다.

Firebase도 그렇습니다. 데이터 저장이라는 교실만 있으면 앱은 돌아가고, 특별한 일이 생겼을 때 다른 방을 찾아가는 것입니다.
</Analogy>

## 언제 필요한가요

세 가지가 대표적입니다. 각각 필요해지는 순간이 다릅니다.

Storage는 사진, 문서, 음성처럼 파일 자체를 보관하는 곳입니다. 사용자가 이미지를 올리는 기능을 만들 때 필요합니다. 자세한 이야기는 [이미지와 파일 업로드](/advanced/file-uploads)에 있습니다.

Functions는 브라우저가 아니라 서버 쪽에서 실행되는 기능입니다. 비밀 값을 다루거나 무거운 처리를 할 때 필요합니다. [서버 기능이 필요할 때](/advanced/serverless-functions)에서 다룹니다.

Realtime Database는 Firestore와 다른 또 하나의 데이터 저장소입니다. 두 가지가 함께 제공되다 보니 헷갈리기 쉽습니다. 지금 만드는 앱이 Firestore로 잘 돌아가고 있다면 옮길 이유가 없습니다.

## 어떻게 시작하나요

기능 이름부터 고르지 마세요. 지금 무엇이 필요한지 말하고 어떤 기능이 맞는지 물어보는 편이 정확합니다.

<PromptBox>
지금 앱은 Firebase의 Firestore에 데이터를 저장하고 Google 로그인을 쓰고 있어.

이번에 추가하고 싶은 기능은 이거야. (여기에 하고 싶은 것을 적습니다.)

이 기능을 만들려면 Firebase에서 무엇이 더 필요한지 알려 줘. 지금 쓰고 있는 기능만으로 되는지도 판단해 줘.

새 기능을 켜야 한다면 그것이 무엇을 하는 기능인지, 요금이나 사용량에서 주의할 점이 있는지도 쉬운 말로 설명해 줘.
</PromptBox>

## 주의할 점

기능을 켜기만 하고 쓰지 않는 상태로 두지 마세요. 열려 있는 기능은 모두 확인할 것이 늘어난다는 뜻입니다.

새 기능을 켤 때마다 접근 권한 설정이 따로 있습니다. 데이터베이스에 보안 규칙이 있듯이 파일 저장소에도 규칙이 있습니다. [보안 규칙이란?](/security/what-are-security-rules)의 판단 기준을 그대로 적용하세요.

<Warning>
Firebase의 무료 사용 범위와 요금 기준은 바뀔 수 있습니다. 파일 저장과 서버 기능은 데이터 저장보다 사용량이 빨리 늘어납니다. 실제로 켜기 전에 공식 안내에서 현재 기준을 확인하세요.
</Warning>

권한 오류가 나면 [Firebase 권한 오류가 나요](/troubleshooting/firebase-permission-error)를 참고하세요.
