## 이것만 알아두세요

지금까지 이 사이트에서는 내 컴퓨터의 폴더를 열고 Claude Code에게 일을 시켰습니다. 이것을 **로컬** 작업이라고 합니다.

Claude Code는 내 컴퓨터가 아니라 Anthropic이 관리하는 컴퓨터(**클라우드**)에서도 일할 수 있습니다. 이렇게 시작한 작업을 클라우드 세션이라고 부릅니다. 노트북을 닫거나 컴퓨터를 꺼도 작업이 계속되고, 휴대폰에서 진행 상황을 확인할 수 있습니다.

대신 조건이 하나 있습니다. 클라우드는 내 컴퓨터의 폴더를 볼 수 없으므로 프로젝트가 **GitHub 저장소**에 올라가 있어야 합니다.

## 쉽게 생각하면

<Analogy>
로컬 작업은 조교를 내 교실로 불러 내 책상에서 일을 시키는 것입니다. 내가 옆에서 보고 있고, 교실 문을 닫으면 일도 멈춥니다.

클라우드 작업은 학교 공용 작업실에 자료 사본을 맡기고 부탁하는 것입니다. 나는 퇴근해도 조교는 계속 일합니다. 다만 작업실에는 내 책상 서랍 속 물건이 없으니, 필요한 자료는 미리 공유 보관함(GitHub)에 올려 두어야 합니다.
</Analogy>

## 언제 필요한가요

아래 같은 경우에 생각해 보세요.

- 오래 걸리는 작업을 맡겨 두고 컴퓨터를 끄고 싶을 때
- 학교 컴퓨터에서 시작한 일을 집이나 휴대폰에서 확인하고 싶을 때
- 데스크톱 앱을 설치할 수 없는 컴퓨터에서 이미 GitHub에 올린 프로젝트를 고치고 싶을 때
- 서로 상관없는 수정 몇 가지를 동시에 맡기고 싶을 때. 작업마다 따로 진행됩니다

처음 만드는 프로젝트라면 로컬이 낫습니다. 만든 웹페이지를 앱 안에서 바로 미리 보고, 고칠 때마다 확인하며 진행할 수 있기 때문입니다. 이 사이트의 기본 과정은 모두 로컬 기준입니다.

## 로컬과 무엇이 다른가요

| | 로컬 | 클라우드 |
| --- | --- | --- |
| 작업하는 곳 | 내 컴퓨터의 폴더 | Anthropic이 관리하는 컴퓨터 |
| 시작하는 곳 | 데스크톱 앱의 Code 영역 | 웹(claude.ai/code), 휴대폰 앱의 Code 탭, 데스크톱 앱 |
| 필요한 것 | 프로젝트 폴더 | GitHub 저장소 |
| 컴퓨터를 끄면 | 작업이 멈춤 | 계속 진행 |
| 결과가 생기는 곳 | 내 폴더 | GitHub 저장소의 새 브랜치 |
| 권한 모드 | 수동, 편집 허용, 계획, 자동 | 편집 허용, 계획, 자동 (수동 없음) |
| 쓸 수 있는 요금제 | Claude Code를 쓸 수 있는 요금제 | 유료 요금제 |

사용량은 로컬과 같은 요금제 사용량에서 차감됩니다. 클라우드 컴퓨터 사용료가 따로 붙지는 않습니다.

## 어떻게 시작하나요

이미 [GitHub에 프로젝트를 올려 본](/code/push-to-github) 상태를 기준으로 설명합니다.

<Steps>
<Step title="claude.ai/code에 들어갑니다">
브라우저에서 claude.ai/code에 들어가 평소 쓰던 Claude 계정으로 로그인합니다. 휴대폰 앱의 Code 탭에서 시작해도 됩니다.

데스크톱 앱에서는 새 작업을 시작할 때 실행 환경을 고르는 곳에서 **Cloud**(클라우드)를 고르면 됩니다. 메뉴 이름은 버전에 따라 다를 수 있습니다.
</Step>
<Step title="GitHub를 연결합니다">
처음 한 번은 GitHub 연결을 요청합니다. 안내에 따라 GitHub 화면에서 승인하고 돌아옵니다.

비공개 저장소를 쓰려면 Claude GitHub 앱 설치도 승인해야 합니다. 이 승인은 사용자가 직접 브라우저에서 합니다.
</Step>
<Step title="저장소를 고릅니다">
입력창 근처의 저장소 선택에서 작업할 프로젝트를 고릅니다. 저장소가 목록에 없다면 아래 "잘 안 된다면"을 보세요.
</Step>
<Step title="권한 모드를 계획으로 맞춥니다">
클라우드에는 매번 묻는 수동 모드가 없습니다. 처음에는 **계획**(Plan)을 고르세요. Claude가 무엇을 어떻게 고칠지 먼저 보여 주고, 내가 승인한 다음에 파일을 고칩니다.
</Step>
<Step title="할 일을 구체적으로 적어 보냅니다">
로컬에서처럼 말로 요청합니다. 클라우드 작업은 옆에서 지켜보지 않는 경우가 많으니 무엇을 바꾸고 어떻게 되면 끝인지까지 적어 두세요.
</Step>
</Steps>

## 이렇게 말해보세요

<PromptBox>
이 저장소는 내가 만든 학급 안내 웹페이지야.

첫 화면의 "이번 주 일정" 제목 아래에 "11월 3일 학부모 상담 주간" 한 줄을 추가해 줘. 다른 부분은 바꾸지 마.

고치기 전에 어떤 파일의 어디를 바꿀지 먼저 알려 주고, 내가 좋다고 하면 진행해 줘.
</PromptBox>

## 결과는 어디서 확인하나요

클라우드 세션은 결과를 바로 반영하지 않습니다. GitHub 저장소에 **새 브랜치**를 만들어 올리고 멈춥니다. 브랜치는 원래 프로젝트를 건드리지 않고 따로 만든 갈래입니다. 자세한 개념은 [Git 조금 더 알기](/advanced/git-advanced)에 있습니다.

<Steps>
<Step title="바뀐 내용을 봅니다">
대화 옆에 바뀐 줄 수(예: +3 -1)가 표시됩니다. 누르면 무엇이 바뀌었는지 볼 수 있습니다. 마음에 들지 않으면 대화창에 이어서 고쳐 달라고 하면 됩니다.
</Step>
<Step title="화면으로 확인합니다">
[Vercel과 연결](/deployment/connect-github-and-vercel)해 두었다면 새 브랜치가 올라갈 때 Vercel이 미리보기 주소를 따로 만들어 줍니다. Vercel 대시보드의 배포 목록에서 찾을 수 있습니다. 이 미리보기 주소는 기본 설정에서 Vercel에 로그인한 본인만 볼 수 있습니다.
</Step>
<Step title="원래 프로젝트에 합칩니다">
괜찮다면 바뀐 내용 표시 근처의 PR 만들기(Create PR) 버튼을 누르거나, Claude에게 "이 변경을 main에 합칠 수 있게 PR을 만들어 줘"라고 부탁합니다. PR(Pull Request)은 "이 갈래의 변경을 원래 프로젝트에 합쳐도 될까요?"라고 묻는 요청서입니다. GitHub에서 그 PR을 합치면(merge) 실제 사이트에도 반영됩니다.
</Step>
</Steps>

## 이렇게 나오면 성공입니다

<Success>
대화 옆에 바뀐 줄 수가 보이고, GitHub 저장소의 브랜치 목록에 Claude가 만든 새 브랜치가 생겼습니다.

브라우저 탭을 닫았다가 claude.ai/code에 다시 들어가도 작업이 목록에 그대로 남아 있습니다.
</Success>

## 주의할 점

<Warning>
내 컴퓨터에만 있는 파일은 클라우드에 없습니다. 특히 `.env.local`처럼 Git에 올리지 않은 설정 파일은 클라우드 세션에서 보이지 않습니다. Firebase 같은 서비스를 연결한 프로젝트라면 설정값이 없어 실행이 안 될 수 있습니다. 이때 설정값을 대화창에 붙여 넣지 말고, 클라우드 환경 설정의 환경변수에 넣는 방법을 Claude에게 물어보세요.
</Warning>

자동이나 편집 허용 모드에서는 Claude가 묻지 않고 파일을 고쳐 새 브랜치에 올립니다. 원래 프로젝트가 바로 바뀌지는 않지만, 합치기 전에는 반드시 바뀐 내용을 확인하세요.

클라우드 세션은 브라우저 탭을 닫아도 멈추지 않습니다. 맡긴 일이 끝나면 쉬는 상태가 됩니다. 다 쓴 작업은 목록에서 보관(Archive)해 두면 깔끔합니다.

## 잘 안 된다면

<Troubleshoot>
<Problem title="GitHub 로그인 버튼만 보이고 진행이 안 돼요">
클라우드 세션은 GitHub 연결이 있어야 시작됩니다. GitHub 계정이 없다면 [GitHub란?](/code/what-is-github)부터 보세요. 학교나 기관 계정이라면 관리자가 GitHub 연결을 허용해야 할 수도 있습니다.
</Problem>
<Problem title="내 저장소가 목록에 없어요">
비공개 저장소는 Claude GitHub 앱이 그 저장소에 설치되어 있어야 보입니다. GitHub 앱 설치 화면에서 해당 저장소에 접근을 허용했는지 확인하세요.
</Problem>
<Problem title="새 프로젝트를 클라우드에서 시작하고 싶어요">
클라우드 세션은 이미 있는 저장소에서 시작합니다. GitHub에서 빈 저장소를 먼저 만들고(README 파일을 함께 만드는 옵션을 고릅니다) 그 저장소를 고르세요. 다만 처음 만드는 프로젝트는 로컬에서 시작하는 편이 확인하기 쉽습니다.
</Problem>
<Problem title="'Claude Code를 쓸 수 없는 계정'이라고 나와요">
클라우드 세션은 유료 요금제에서 쓸 수 있습니다. 학교나 기관 계정이라면 Claude Code가 포함된 좌석인지 관리자에게 확인하세요.
</Problem>
</Troubleshoot>

## G쌤 팁

<TeacherTip>
클라우드의 가장 큰 장점은 컴퓨터를 켜 두지 않아도 된다는 점입니다. 퇴근 전에 맡겨 두고, 다음 날 아침 휴대폰으로 결과를 확인할 수 있습니다.

처음에는 이미 GitHub와 Vercel에 올려 둔 프로젝트에서 문장 하나 바꾸기처럼 작은 일로 시작해 보세요. 브랜치, 미리보기 주소, PR 합치기가 한 번에 이해됩니다. 새 프로젝트를 만드는 일은 지금처럼 로컬에서 하시면 됩니다.
</TeacherTip>
