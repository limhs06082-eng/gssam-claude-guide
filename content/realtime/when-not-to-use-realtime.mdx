## 이것만 알아두세요

실시간은 좋은 기능이지만 모든 앱에 필요하지는 않습니다.

기준은 하나입니다. 같은 데이터를 두 개 이상의 화면이 동시에 보고 있느냐입니다. 아니라면 붙이지 않는 편이 낫습니다.

## 필요 없는 경우

**혼자 한 화면에서 쓰는 앱.** 개인 메모, 나만 보는 업무 목록, 개인 설정 같은 것입니다. 내가 바꾼 것을 내가 보는 것뿐이므로 실시간이 할 일이 없습니다.

**한 사람이 순서대로 쓰는 앱.** 학교에서 쓰고 집에서 이어서 쓰는 앱이라면, 열 때 최신 내용이 나오면 충분합니다. 두 곳을 동시에 켜 두지 않기 때문입니다.

**입력하는 사람이 정해져 있는 앱.** 교사만 입력하고 나중에 확인하는 기록용 앱이라면 새로고침으로 충분합니다.

**보여 주기만 하는 앱.** 소개 홈페이지, 안내문, 자료 목록처럼 사용자가 입력하지 않는 앱입니다.

**바뀌는 일이 드문 데이터.** 학기에 몇 번 바뀌는 명단이나 연간 일정 같은 것입니다. 바뀔 일이 없는데 연결을 열어 둘 이유가 없습니다.

## 붙이면 무엇이 늘어나나요

필요 없는데 붙이면 이런 것들이 늘어납니다.

**정리할 것이 늘어납니다.** 화면을 떠날 때 연결을 정리해야 하고, 같은 연결이 여러 번 만들어지지 않게 챙겨야 합니다.

**고장 날 곳이 늘어납니다.** 연결이 끊기거나 다시 이어지지 않는 상황을 처리해야 합니다.

**사용량이 늘어납니다.** 화면을 켜 둔 동안 계속 데이터를 주고받습니다. 연습 단계에서는 문제가 없지만, 실제로 여러 사람이 쓰는 앱이라면 신경 써야 합니다.

**얻는 것이 없을 수 있습니다.** 혼자 쓰는 앱에서는 실시간을 붙여도 화면이 달라 보이지 않습니다.

## 판단해 봅시다

만들려는 앱에 대해 두 가지만 답해 보세요.

**"이 앱을 두 화면에 동시에 켜 놓을 일이 있습니까?"** 사람이 여럿이든 나 혼자든 상관없습니다. 컴퓨터와 휴대폰을 함께 보는 것도 두 화면입니다.

**"상대가 바꾼 것을 몇 초 안에 알아야 합니까?"** 나중에 열어 봤을 때 알면 되는 정보라면 실시간이 필요 없습니다.

둘 다 아니라면 앞 과정에서 만든 방식으로 충분합니다.

| 만들려는 앱 | 실시간 |
| --- | --- |
| 개인 업무 체크리스트 | 필요 없습니다 |
| 학교와 집에서 이어 쓰는 목록 | 필요 없습니다 |
| 교사만 기록하는 상담 일지 | 필요 없습니다 |
| 학급 소개 홈페이지 | 필요 없습니다 |
| 모둠 활동 상태판 | 필요합니다 |
| 과제 제출 현황 | 필요합니다 |
| 여러 선생님이 함께 채우는 목록 | 필요합니다 |
| 실시간 퀴즈나 투표 | 필요합니다 |

## 이미 붙였다면

써 보니 필요 없다고 판단되면 빼도 됩니다. 데이터는 그대로 남습니다.

<PromptBox>
이 앱에 붙인 실시간 연결을 빼고, 앱을 열 때와 새로고침할 때만 Firestore에서 데이터를 가져오도록 되돌려 줘.

저장하고 불러오고 수정하고 삭제하는 기능은 그대로 두고, 실시간으로 화면이 갱신되는 부분만 정리해 줘. 남아 있는 연결이 없는지도 확인해 줘.

기존 기능과 디자인은 변경하지 마.
</PromptBox>

되돌린 뒤에도 저장한 데이터는 그대로 있습니다. 여러 기기에서 같은 내용을 보는 것도 그대로 됩니다. 새로고침이 다시 필요해질 뿐입니다.

## 기능보다 필요가 먼저입니다

이 과정에서 배운 기술은 실시간 동기화지만, 더 중요한 것은 판단하는 습관입니다.

새 기능을 알게 되면 써 보고 싶어집니다. 그런데 앱은 기능이 많을수록 좋은 것이 아니라, 필요한 일을 잘할수록 좋은 것입니다.

같은 기준을 [언제 데이터베이스가 필요한가요?](/database/when-you-need-a-database)와 [왜 로그인이 필요한가요?](/auth/why-login)에서도 만나게 됩니다. 무엇이 필요한지 먼저 정하고 기술은 나중에 고릅니다.
