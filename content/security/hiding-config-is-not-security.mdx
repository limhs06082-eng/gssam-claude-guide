## 이것만 알아두세요

Firebase 웹 설정값은 브라우저에 노출되도록 만들어진 공개 설정값입니다. 이 값을 숨기는 것이 보안이 아닙니다.

다만 모든 설정값이 공개해도 되는 것은 아닙니다. 절대 노출하면 안 되는 값도 따로 있습니다. 이 페이지는 그 둘을 구분합니다.

## 왜 이런 질문이 나오나요

[환경변수란?](/database/environment-variables)에서 Firebase 설정값을 `.env.local` 파일에 넣고 Git에 올리지 않도록 했습니다.

그러다 보면 자연스럽게 이렇게 생각하게 됩니다. "이 값이 새어 나가면 큰일 나겠구나. 잘 숨기면 안전하겠구나."

절반만 맞습니다. 값을 관리하는 방식으로는 좋지만, 그것으로 데이터가 지켜지지는 않습니다.

## 쉽게 생각하면

<Analogy>
학교 주소와 현관 열쇠의 차이입니다.

학교 주소는 누구나 압니다. 홈페이지에도 적혀 있고 지도에도 나옵니다. 주소를 안다고 해서 아무나 교무실에 들어갈 수 있는 것은 아닙니다. 문이 잠겨 있기 때문입니다.

Firebase 웹 설정값은 주소에 가깝습니다. "이 앱은 이 데이터베이스를 사용합니다"라고 알려 주는 값입니다. 브라우저가 데이터베이스를 찾아가려면 이 값이 필요하므로, 애초에 감출 수 없습니다.

문을 잠그는 일은 따로 해야 합니다. 그것이 보안 규칙입니다.
</Analogy>

## 실제로 확인해 볼 수 있습니다

브라우저에서 웹페이지의 소스 보기 기능을 열면, 화면을 그리는 코드가 그대로 보입니다.

Firebase 웹 설정값은 그 안에 들어 있습니다. 감춘 것처럼 보여도, 브라우저가 읽어야 하는 값이므로 결국 브라우저까지 전달됩니다.

이것은 잘못 만들어서가 아니라 원래 그렇게 설계된 것입니다. 그래서 Firebase는 값을 숨기는 대신 다른 방법으로 데이터를 지킵니다.

## 공개해도 되는 값과 절대 안 되는 값

여기서 지나치게 단순화하면 위험합니다. "설정값은 다 공개해도 된다"고 이해하면 안 됩니다.

| 구분 | 예 | 어디까지 갈 수 있나 |
| --- | --- | --- |
| 공개 설정값 | Firebase 웹 설정값 | 브라우저까지 전달됨. 보안 규칙이 접근을 제한 |
| 비밀값 | 서비스 계정 키, 관리자 키, API secret | 브라우저에 전달하면 안 됨. 규칙을 우회할 수 있음 |

<Warning title="이 값들은 절대 노출하지 않습니다" variant="danger">
서비스 계정 키나 관리자 권한을 가진 키는 성격이 완전히 다릅니다. 이런 값은 보안 규칙을 건너뛰고 데이터에 접근할 수 있도록 만들어진 것입니다.

이런 값은 브라우저로 보내는 코드에 넣지 않고, Git 저장소에도 올리지 않고, 대화창이나 문서에 붙여 넣지도 않습니다.

초보 단계에서 만드는 앱에는 이런 키가 필요하지 않습니다. Claude가 서비스 계정 키를 쓰자고 제안하면, 왜 필요한지 먼저 물어보세요. 대부분은 다른 방법이 있습니다.
</Warning>

## 그래도 환경변수를 쓰는 이유

공개 설정값이라면 코드에 그냥 적어도 될 것 같지만, 여전히 환경변수를 씁니다. 이유가 세 가지입니다.

**연습용과 실제용을 바꾸기 쉽습니다.** 나중에 데이터베이스를 하나 더 만들어도 값만 바꾸면 됩니다.

**공개 값과 비밀값을 같은 자리에서 관리하게 됩니다.** 나중에 비밀값이 생겼을 때 실수로 코드에 적어 넣는 일을 줄여 줍니다.

**습관이 됩니다.** 설정값은 코드 밖에 둔다는 습관이 있으면, 정말 위험한 값을 다룰 때도 자연스럽게 같은 방식을 씁니다.

배포할 때는 [Vercel에 환경변수 등록하기](/deployment/environment-variables-on-vercel)에서 같은 값을 등록합니다.

## 그럼 무엇이 진짜 보안인가요

데이터를 지키는 것은 서버 쪽 규칙입니다.

설정값을 알아도, 요청을 직접 보내도, 규칙에서 "로그인하지 않은 사람은 읽을 수 없다"고 정해 두었다면 데이터는 나오지 않습니다. 이 판단은 내 브라우저가 아니라 Firebase 쪽에서 이루어지므로 사용자가 고칠 수 없습니다.

다음 페이지 [보안 규칙이란?](/security/what-are-security-rules)에서 그 규칙을 다룹니다. 이 과정에서 가장 중요한 페이지입니다.
