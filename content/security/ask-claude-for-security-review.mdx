## 이것만 알아두세요

보안 규칙과 데이터 접근 코드를 Claude에게 점검해 달라고 하면, 놓친 부분을 찾아 줍니다.

다만 이 점검은 스스로 확인하는 습관이지 전문 보안 감사가 아닙니다. 마지막 판단은 사용자가 합니다.

## 무엇을 점검해 달라고 해야 하나요

"보안 점검해 줘"라고만 하면 원론적인 답이 돌아옵니다. 무엇을 보라고 짚어 주면 훨씬 정확해집니다.

이 과정에서 다룬 네 가지를 그대로 쓰면 됩니다.

- 로그인하지 않은 사람이 데이터를 읽거나 쓸 수 있는 곳이 있는가
- 로그인한 사람이 남의 데이터를 읽을 수 있는 구조가 있는가
- 화면에서만 막고 규칙에서는 막지 않은 동작이 있는가
- 저장할 필요가 없는 정보를 저장하고 있는가

## 직접 해봅시다

<Steps>
<Step title="Claude Code 앱에서 프로젝트를 엽니다">
배포하려는 프로젝트를 엽니다.
</Step>
<Step title="아래 점검 요청을 보냅니다">
고치기 전에 설명부터 하도록 요청하는 것이 중요합니다.
</Step>
<Step title="설명을 읽고 무엇을 고칠지 정합니다">
전부 고칠 필요는 없습니다. 어떤 지적은 이 앱에 해당하지 않을 수 있습니다.
</Step>
<Step title="고친 뒤 직접 확인합니다">
시크릿 창과 두 번째 계정으로 실제로 확인합니다. 고쳤다는 말만 믿지 않습니다.
</Step>
</Steps>

## 이렇게 말해보세요

<PromptBox>
현재 Firebase 보안 규칙과 데이터 접근 코드를 확인해서, 로그인하지 않은 사용자가 데이터를 읽거나 수정할 수 있는 부분이 있는지 점검해 줘.

그리고 로그인한 사용자가 다른 사용자의 데이터를 읽거나 고칠 수 있는 구조가 있는지도 함께 봐 줘.

문제가 있으면 어느 파일의 어느 부분이 왜 문제인지 먼저 설명하고, 내가 확인한 뒤에 고쳐 줘.
</PromptBox>

마지막 문장이 핵심입니다. 바로 고치게 하면 무엇이 왜 바뀌었는지 모르는 채로 넘어갑니다. 설명을 먼저 받으면 다음 앱을 만들 때 같은 실수를 피할 수 있습니다.

## 이어서 물어볼 것

첫 점검이 끝나면 저장하는 데이터도 함께 봅니다.

<PromptBox title="이어서 이렇게 말해보세요">
이 앱이 데이터베이스에 저장하는 항목을 전부 목록으로 보여 주고, 각 항목이 어떤 기능에 쓰이는지 알려 줘.

어디에서도 쓰이지 않는 항목이나, 개인정보에 해당하는 항목이 있으면 따로 표시해 줘.

그리고 API 키나 비밀값이 코드나 Git에 올라가는 파일에 들어 있는지도 확인해 줘. 지우거나 고치는 작업은 내가 확인한 뒤에 해 줘.
</PromptBox>

## 이렇게 나오면 성공입니다

<Success>
어느 파일의 어느 부분이 문제인지 구체적으로 나옵니다. "보안에 유의하세요" 같은 일반적인 조언만 나온다면 질문을 더 좁혀야 합니다.

지적된 내용을 읽고 무슨 뜻인지 이해할 수 있습니다. 이해되지 않으면 "이게 실제로 어떤 상황에서 문제가 되는지 예를 들어 설명해 줘"라고 다시 물어보세요.

고친 뒤 시크릿 창에서 앱을 열면 데이터가 하나도 나오지 않습니다.

두 번째 계정으로 로그인했을 때 첫 계정의 데이터가 보이지 않습니다.
</Success>

## 이 점검이 대신하지 못하는 것

<Warning title="전문 보안 감사와는 다릅니다">
Claude의 점검은 코드와 규칙을 읽고 흔한 문제를 찾아 주는 일입니다. 다음은 대신해 주지 못합니다.

- 실제로 공격해 보면서 확인하는 일
- 소속 기관의 개인정보 지침에 맞는지 판단하는 일
- 이 앱에 어떤 데이터를 담아도 되는지 결정하는 일
- 놓친 문제가 하나도 없다고 보증하는 일

점검 결과에 아무 문제가 없다고 나와도, 그것이 안전하다는 증명은 아닙니다. 확인해야 할 것을 확인했다는 뜻입니다.

민감한 데이터를 다루는 앱이라면 여기서 멈추고, 기관의 담당자와 먼저 상의하세요.
</Warning>

## 배포 전 마지막 확인 목록

인터넷에 공개하기 전에 다음을 직접 확인하세요. 다섯 가지 모두 브라우저만 있으면 됩니다.

- Firebase 규칙 화면에 만료 날짜가 적힌 임시 규칙이 남아 있지 않습니까?
- 시크릿 창으로 앱을 열었을 때 데이터가 보이지 않습니까?
- 두 번째 계정으로 로그인했을 때 첫 계정의 데이터가 보이지 않습니까?
- 저장하고 있는 항목을 전부 말할 수 있고, 각각 왜 필요한지 설명할 수 있습니까?
- 연습용으로 넣어 둔 데이터가 남아 있지 않습니까?

배포 이후에는 [배포 후 로그인 테스트하기](/deployment/login-after-deploy)에서 한 번 더 확인합니다. 배포 주소에서는 로컬과 다르게 동작하는 부분이 있습니다.

## G쌤 팁

<TeacherTip>
저는 점검 결과를 받고 "문제 없다"는 말에 안심했다가, 정작 규칙 화면을 열어 보지 않았던 적이 있습니다. Claude는 프로젝트 폴더 안의 파일을 읽었는데, 실제로 적용된 규칙은 콘솔에서 따로 바뀌어 있었습니다.

파일에 적힌 규칙과 실제로 적용된 규칙이 다를 수 있습니다. 점검이 끝나면 Firebase 콘솔의 규칙 화면을 직접 한 번 열어 보세요.

그리고 위의 다섯 줄은 종이에 적어서 옆에 두세요. 배포할 때마다 같은 순서로 확인하면 습관이 됩니다.
</TeacherTip>
